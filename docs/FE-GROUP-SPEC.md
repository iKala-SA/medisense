## 1. 定位

1. 群組是一組成員 e-mail 的名單。**目前群組不影響任何人的存取權**，管理介面只認使用者的系統角色（見 `BE-GROUP-SPEC.md` 第 5 節）。
2. 群組的成員名單目前僅供分享功能使用。分享功能不在本頁範圍。
3. 前端依 `me.permissions` 的判斷只作為 UI 便利；實際權限以後端為準（`AGENTS.md` 原則 5）。

## 3. 頁面結構

本頁有兩種畫面，由同一元件以狀態切換：

1. **列表畫面**（預設）：群組表格、搜尋、建立群組（需 `groups`）、重新整理。
2. **編輯畫面**：點選列表中的群組（或建立後自動進入）後，以編輯畫面取代內容區。**單頁**（不使用分頁籤），由上而下為：
   - 標題列：返回按鈕、群組名稱、**刪除群組**按鈕（危險樣式；唯讀時不顯示）
   - 摘要：「成員 N 人。群組目前不影響使用者的存取權限。」
   - **基本資料**區塊
   - **成員**區塊

兩個區塊的標題列各有一個 `Toggle`（`ListKit.jsx`），可上下收攏或展開，預設展開。收合只以 `display:none` 隱藏內容，**不卸載元件**，因此未儲存的基本資料與已載入的成員清單會保留。

「返回」按鈕回到列表並重新載入。

## 4. 列表畫面

### 4.1 標題列

| 元素 | 文字／圖示 | 條件 | 行為 |
|---|---|---|---|
| 標題 | 群組管理（UsersThree） | 永遠顯示 | — |
| 按鈕 | 重新整理（ArrowClockwise） | 列表畫面且可檢視；`busy` 時 disabled，圖示旋轉 | 重新呼叫 `GET /api/groups`；失敗時保留目前列表 |
| 按鈕（主要） | 新增群組（Plus） | 列表畫面且具 `groups` 權限 | 開啟建立對話框 |

### 4.2 說明文字

「建立群組並維護成員名單。群組目前不影響使用者的存取權限。」

### 4.3 表格

| 欄位 | 內容 |
|---|---|
| 名稱 | 粗體 |
| 說明 | 灰色；空值顯示「—」 |
| 成員數 | `member_count`；若無則以 `member_emails` 長度計算，再無則為 0 |
| 箭頭 | 視覺指示（CaretRight） |

- 整列可點擊（含鍵盤 Enter）進入編輯畫面。
- 排序：後端依名稱不分大小寫排序，前端不另行排序。
- 搜尋框（`ListToolbar`，placeholder「搜尋群組名稱或說明」）：比對名稱與說明，不分大小寫，即時過濾。群組數量少，不分頁。
- 空狀態：「尚未建立任何群組。」；無搜尋結果：「沒有符合條件的群組。」

### 4.4 建立群組對話框

| 欄位 | 規則 |
|---|---|
| 群組名稱 | 必填，去除前後空白後 1–80 字；`maxLength={80}`；placeholder「例如：護理部」。空白顯示「請輸入群組名稱」；超過 80 字顯示「群組名稱不可超過 80 字」，皆不送出 |
| 說明 | 選填，`maxLength={500}` |

- 按「建立」（處理中為「建立中…」且 disabled）→ `POST /api/groups`（不含成員）。成功後直接進入該群組的編輯畫面，方便接著加入成員。
- 同名允許（2026-10-30 決定，見 BE 規格 §2.1），不會因名稱重複而失敗。
- 錯誤以 `friendly()` 轉為中文（見第 7 節）。

## 5. 編輯畫面

### 5.1 標題列

- 左上「返回群組列表」（ArrowLeft，aria-label）。若基本資料有未儲存變更，先確認「放棄未儲存的變更？」。
- 標題：群組名稱。
- 右上「刪除群組」按鈕（見 5.4；唯讀時不顯示）。

### 5.2 成員區塊

#### 5.2.1 成員清單

| 欄位 | 內容 |
|---|---|
| 選取 | 勾選框（aria-label「選取 {email}」），用於批次移出，見 5.2.3 |
| 姓名與 email | 姓名（無則顯示「（尚未登入）」）；下方為 email（小字） |
| 帳號狀態 | `has_account` 為 false：「帳號不存在」（琥珀色）；`status` 為 `suspended`：「停用」（紅）；其餘：「啟用」（綠） |
| 操作 | 移除（垃圾桶，aria-label「移除 {email}」） |

- 來源：`GET /api/groups/{id}/members`，載入一次；加入或移出後重新載入。
- 區塊標題顯示人數：「成員（N）」。
- 搜尋（aria-label「搜尋成員」，placeholder「搜尋姓名、電子郵件或科別」）：比對姓名、email、科別，不分大小寫，即時過濾；搜尋變更時頁碼重設為 1。
- 分頁：前端分頁，每頁 30 筆；超過 30 筆時顯示「共 N 人，第 X / Y 頁」與上一頁、下一頁。
- 空狀態：「尚未加入成員。」（有成員但搜尋無結果時為「沒有符合條件的成員。」）
- 成員上限 1000 人（後端限制）。

#### 5.2.2 加入成員對話框（已實作）

- 位置：成員區塊工具列的「加入成員」按鈕（UserPlus，主要樣式；唯讀時不顯示）。
- 對話框內有「搜尋使用者」輸入框（placeholder「搜尋姓名、電子郵件或科別」），手動輸入框 aria-label「手動輸入電子郵件」；送出按鈕「加入」（處理中為「加入中…」）。
- 說明文字：「只能加入已存在的帳號（含預先註冊）。新帳號請先到「使用者管理」預先註冊。」
- **候選清單**：來源 `GET /api/users`，開啟對話框時載入一次。
  - 比對姓名、email、科別，不分大小寫；排除已在群組中的人。
  - **排除已停用帳號**（FE 規格 Q1 的決定）。已停用者仍可用手動輸入加入。
  - 最多顯示 30 筆；點選切換選取，已選的項目右側顯示「已選」，未選取者右側顯示科別。
  - 無可加入者：「沒有可加入的使用者」。
  - 使用者清單載入失敗：通知「無法載入使用者清單（仍可手動輸入電子郵件）：{錯誤訊息}」。
- **已選清單**：以 chip 顯示，每個 chip 可取消選取。
- **手動輸入**：多行文字框，以逗號（半形或全形）、分號、空白或換行分隔。
- **空白檢查**（送出前）：未選取且未輸入任何內容時，顯示「請選擇或輸入電子郵件」，不送出。
- **格式檢查**（送出前）：每筆 e-mail 轉小寫後需含 `@` 且不含空白（與後端相同，BE 規格 Q2）。不合格者列在錯誤訊息「格式不正確：{清單}」，不送出。
- **上限檢查**：目前成員數加上本次數量超過 1000 時，顯示「群組成員不可超過 1000 人」，不送出。
- **送出**：每 100 筆為一批呼叫 `POST /api/groups/{id}/members`，依序合併結果。
- **送出例外**：API 呼叫失敗（非 2xx）時，以 `friendly()` 轉換後顯示於對話框內，對話框保持開啟；清單不重新載入（見 Q8）。
- **結果**：
  - 無未加入者（略過者不算未加入）：通知「已加入 N 人，略過 M 人」，對話框關閉，成員清單重新載入。
  - 有未加入者：對話框保持開啟，列出「已加入 N 人，略過 M 人，未加入 K 人」與每位未加入者的原因：
    - `invalid_email` → 格式不正確
    - `domain_not_allowed` → 網域不在允許清單
    - `not_a_registered_account` → 尚未建立帳號（請先到使用者管理預先註冊）
  - 按鈕由「加入」變為「完成」，按「完成」關閉並重新載入清單。
- **未實作**：對話框內未送出內容的離開確認（見第 9 節 G11）。

#### 5.2.3 批次選取與移出（已實作，2026-10-30）

- 成員清單每列有勾選框（aria-label「選取 {email}」）；表頭勾選框（「選取本頁所有成員」）切換本頁全部成員。
- 選取狀態跨頁保留；搜尋條件變更時清空選取。
- 有選取時，工具列顯示「已選 N 人」與「移出所選」按鈕。
- 按「移出所選」（處理中 disabled）→ 確認對話框，標題「批次移出成員」，內文「確定要將所選的 N 位成員移出「{群組名稱}」？」，按鈕「取消」與「移出」（處理中為「移出中…」）。
- 後端沒有批次移除端點：前端對每個 e-mail 依序呼叫 `DELETE /api/groups/{id}/members/{email}`。
- 全部成功：通知「已移出 N 人」，關閉對話框，清空選取。
- 部分失敗：通知「已移出 N 人，M 人失敗」，對話框保持開啟並列出失敗的 e-mail 與原因；失敗的項目保留選取，可直接重試。

#### 5.2.4 移出單一成員對話框（已實作）

- 按垃圾桶 → 確認對話框（標題「移出成員」）：「確定要將 {email} 移出「{群組名稱}」？」
- 按「移出」→ `DELETE /api/groups/{id}/members/{email}`，處理中按鈕 disabled。
- 成功：通知「已移出 {email}」，關閉對話框，清單重新載入。
- 失敗：通知錯誤訊息，**對話框保持開啟**。
- 不需要填寫理由。

### 5.3 基本資料區塊

- 欄位：群組名稱（`maxLength={80}`）、說明（`maxLength={500}`）。
- 儲存按鈕「儲存」（處理中為「儲存中…」）：只有在內容（名稱、說明或角色）與目前群組不同時可按；唯讀時不顯示。
- **角色**欄位（2026-10-30 新增與調整）：
  - 已關聯的角色以**緊湊的 tag** 顯示（chip，可移除，aria-label「移除角色 {名稱}」），與搜尋框同一列排列，節省版面（2026-10-30 調整）。
  - 新增方式為 **Search box**（aria-label「搜尋角色」；無已選角色時 placeholder 為「搜尋角色名稱或代號」）：輸入角色名稱或代號時，即時過濾符合條件的角色（不分大小寫，包含即符合）。
  - 待選清單以**浮層**顯示於搜尋框下方，只在搜尋框取得焦點或有輸入時出現，不佔用版面（2026-10-30 調整）。**待選清單最多顯示 10 筆**。超過 10 筆時顯示「僅顯示前 10 筆，請輸入更多條件縮小範圍」；符合數為 0 時顯示「沒有符合的角色」。
  - 待選清單排除已關聯的角色；輸入為空時顯示前 10 筆待選角色。
  - 點選待選項目，或在輸入框按 Enter 選取第一筆符合項目；選取後加入 chip，清空輸入框。
  - 角色清單來自 `GET /api/roles`（一次載入）。**`admin` 與 `user` 皆列入可選清單**（2026-10-30 調整，原為不可選）。目前待選清單實際為 `GET /api/roles` 回傳的全部角色（另含 `builder` 與自訂角色），見 Q10。
  - 角色清單載入失敗時不通知；待選處持續顯示「角色清單載入中…」，已關聯的角色仍以代號顯示（見 Q9）。
  - 角色只記錄關聯，**不影響任何功能的存取權限**，欄位旁有說明文字。
- 儲存：`PATCH /api/groups/{id}`，送出 `name`、`description` 與 `role_ids`；成員名單不會被覆寫。成功後通知「已更新群組」，並更新標題與摘要。
- 名稱為空時顯示「請輸入群組名稱」，超過 80 字時顯示「群組名稱不可超過 80 字」，皆不送出。API 失敗時以 `friendly()` 轉換後顯示於表單內。
- 有未儲存變更時，按返回會先確認（見 5.1）。

### 5.4 刪除群組

- 位置：編輯畫面標題列「刪除群組」按鈕（危險樣式）。
- 確認對話框：標題「刪除群組」；內文「確定要刪除「{群組名稱}」？群組的 {N} 位成員名單將一併刪除。」（N 為目前成員人數）。
- 按「刪除」→ `DELETE /api/groups/{id}`，處理中按鈕文字為「刪除中…」且 disabled。
- 成功：通知「已刪除群組」，返回列表並重新載入。
- 失敗：通知錯誤訊息，**對話框保持開啟**。

## 6. 未儲存變更與關閉

| 操作 | 行為 |
|---|---|
| 返回群組列表 | 基本資料有未儲存變更時，先確認「放棄未儲存的變更？」 |
| 新增群組對話框 | 點遮罩、✕ 或「取消」直接關閉，無確認；處理中仍可關閉 |
| 收合基本資料區塊 | 不確認；內容保留（未儲存的變更仍在），展開後可繼續編輯 |
| 成員加入／移出 | 即時送出，不屬於未儲存變更 |
| 加入成員對話框 | 點遮罩或 ✕ 直接關閉（**未實作**未送出內容的確認） |
| 批次移出對話框 | 處理中不可關閉；部分失敗時保持開啟 |
| 刪除、移出確認對話框 | 點遮罩或取消關閉（處理中時不可關閉） |

## 7. 提示與錯誤

### 7.1 成功提示（通知）

| 動作 | 文字 |
|---|---|
| 建立群組 | 已建立群組 |
| 更新基本資料 | 已更新群組 |
| 加入成員 | 已加入 N 人，略過 M 人 |
| 移出成員 | 已移出 {email} |
| 批次移出成員 | 已移出 N 人；部分失敗時為「已移出 N 人，M 人失敗」 |
| 刪除群組 | 已刪除群組 |

### 7.2 錯誤對照（`friendly()`）

`api.js` 的 `call()` 在非 2xx 時拋出 `Error("{狀態碼} {detail}")`。`friendly()` 依下列順序轉為中文：

| 條件 | 顯示 |
|---|---|
| 訊息包含 `member limit` | 群組成員不可超過 1000 人 |
| 403 | 權限不足，請聯絡系統管理員 |
| 404 | 此群組或成員已不存在，請重新整理 |
| 422（其他） | 資料格式不正確，請檢查輸入內容 |
| 其他 | 操作失敗：{原始訊息} |

- 同名不再回錯誤（見 BE 規格 §2.1）。
- 錯誤以繁體中文呈現；後端英文原文只在「其他」類別中保留。
- 載入失敗通知：列表為「無法載入群組：{錯誤訊息}」；成員清單為 `friendly()` 轉換後的訊息；候選使用者為「無法載入使用者清單（仍可手動輸入電子郵件）：{錯誤訊息}」。角色清單載入失敗不通知（見 5.3）。

## 8. 與使用者管理的關係（命名衝突）

| 項目 | 群組管理頁（本頁） | 使用者管理頁 |
|---|---|---|
| 「群組」指的是 | `groups` 集合：管理員自行建立的群組，可無限新增 | `users.department` 欄位的值，固定 12 個科別（`schemas.DEPARTMENTS`），畫面上標示為「群組」 |
| 資料來源 | `GET /api/groups` | 固定清單，由後端 `DEPARTMENTS` 提供 |
| 寫入位置 | 本頁 | 使用者管理的預先註冊與編輯 |

- 兩者是不同的資料，仍共用「群組」一詞。
- **2026-10-30 決定**：使用者管理頁的 `Group` 篩選器已移除（`FE-USER-SPEC.md` 第 3.3 節）。使用者管理頁的「群組」欄位只對應固定科別。
- 本頁的候選清單（加入成員）使用使用者清單，只用於挑選帳號，不依科別篩選。
