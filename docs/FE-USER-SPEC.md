## 2. 頁面結構

本頁有兩種畫面，由同一元件以狀態切換：

1. **列表畫面**（預設）：`UsersPage`
2. **編輯畫面**：點選列表任一列後，以 `UserEdit` 取代整個內容區；按「返回使用者列表」或取消預先註冊後返回時會重新載入列表；按「儲存變更」則停留在編輯畫面。

另有一個**預先註冊對話框**（`AddModal`），疊在列表畫面上。

## 3. 列表畫面

### 3.1 標題列與按鈕

| 元件 | 文字 / 圖示 | 狀態條件 | 行為 |
|---|---|---|---|
| 標題 | 使用者管理 | 永遠顯示 | — |
| 按鈕 | 重新整理（ArrowClockwise） | `busy` 時 disabled；執行中圖示旋轉 | 重新呼叫 `GET /api/users`（僅在點擊時）。失敗時只顯示 toast，不自動重試。 |
| 按鈕 | 匯出 CSV（DownloadSimple） | 僅 `canEdit` 顯示；`exporting` 或 `dir` 尚未載入時 disabled | 呼叫 `GET /api/users/export.csv`，以 Blob 存為 `tcvgh-accounts.csv`；成功 toast「已匯出帳號清冊」，失敗 toast「匯出失敗：…」 |
| 按鈕（主要） | 預先註冊（UserPlus） | 僅 `canEdit` 顯示 | 開啟預先註冊對話框 |

頁面副標題（標題列下方）：「管理同仁的平台角色、所屬群組與帳號狀態。角色與狀態變更需填寫原因，並寫入稽核記錄。」

**載入時機**：使用者清單在頁面掛載且 `canView` 時載入一次（2026-10-30 起不再載入群組清單）。不得以會隨每次渲染改變的函式（例如 `notify`）作為重新載入的依賴，否則載入失敗後會循環重新呼叫 API。

### 3.2 統計卡片

- 共分為三張卡片 `使用者人數`、`啟用人數`、`停用人數`。數字統計所有已載入的使用者，不受搜尋與篩選影響。
- 這個區塊預設為展開。統計區塊上方右側有一個小字 `+` 按鈕（無障礙標籤為「收合統計」／「展開統計」），點選可收合或展開整個統計卡片區塊。

### 3.3 搜尋與分頁籤（ListToolbar）

**搜尋框**

- placeholder：「搜尋姓名或電子郵件」
- 即時過濾（每次輸入都更新，無防抖動）
- 比對欄位：`name`、`email`，不分大小寫，去除前後空白；**不包含角色與狀態**
- 搜尋字串變更時，頁碼重設為第 1 頁

**過濾欄位**

- 「角色」下拉（無障礙標籤「角色」）：可選取特定角色（系統管理員、Agent 建置者、一般使用者），預設為「全部角色」
- **2026-10-30 決定**：移除原 `Group` 篩選器。欄位「群組」（`department`）不提供篩選，避免與群組管理頁的群組混淆（見 `FE-GROUP-SPEC.md` 第 8 節）。
- 角色下拉與搜尋框、分頁籤為 AND 關係；任一條件變更時，頁碼重設為第 1 頁。

**分頁籤**（單選，預設「全部」）

| 分頁籤 | 篩選條件 |
|---|---|
| 全部 | 不篩選 |
| 啟用 | `status !== 'suspended'` |
| 停用 | `status === 'suspended'` |

- 分頁籤與搜尋條件為 AND 關係。
- 切換分頁籤時，頁碼重設為第 1 頁。
- 目前沒有角色分頁籤；角色條件由上方「過濾欄位」的「角色」下拉處理。

### 3.4 表格

**欄位**（六欄，欄寬比例 `1.6fr 1fr 1fr .9fr 1fr 24px`）

| 欄位 | 內容與規則 |
|---|---|
| 姓名 | 頭像（姓名或電子郵件的第一個字母，大寫）＋姓名；無姓名時顯示「（尚未登入）」；於姓名下方以小字顯示 `email`，超出時省略號 |
| 群組 | `department`，空值顯示「—」 |
| 角色 | 角色徽章：系統管理員（brand）、Agent 建置者（soft）、一般使用者（預設） |
| 狀態 | 依序判斷：`suspended` → 停用（紅）；其餘 → 啟用（綠）。無 `uid` 的預先註冊帳號同樣顯示為啟用。 |
| 最近登入 | `last_seen_at` 以 zh-TW 格式顯示；無值顯示「—」 |
| 箭頭 | 視覺指示，無獨立功能 |

- **列排序**：後端回傳時依 `last_seen_at` 由新到舊排序；前端不另行排序。
- **列點擊**：整列可點擊（游標為指標），進入該使用者的編輯畫面。
- **空狀態**：
  - 原始資料為空：「目前沒有使用者資料。」
  - 有資料但篩選後為空：「沒有符合條件的使用者。」

### 3.5 分頁

- 每頁 **30 筆**，前端分頁（不是伺服器分頁）。
- 篩選後的列表筆數超過 30 筆時才顯示分頁列：「共 N 人，第 X / Y 頁」，附「上一頁」「下一頁」按鈕。分頁依篩選結果計算。
- 第一頁時「上一頁」disabled；最後一頁時「下一頁」disabled。

### 3.6 載入與錯誤

- 資料尚未載入時（`dir === null`），表格區域顯示載入中提示（文字「載入中…」）。
- 載入失敗：toast「載入使用者失敗：…」。若先前沒有資料，列表以空資料呈現（顯示「目前沒有使用者資料。」）；若已有資料（例如按「重新整理」失敗），保留原列表。

## 4. 預先註冊對話框

**觸發**：列表標題列「預先註冊」按鈕。

**標題與說明**

- 標題：預先註冊使用者
- 說明：「同仁首次以院內 Google 帳號登入時，會套用此角色與群組。」

**欄位**

| 欄位 | 控制項 | 預設值 | 規則 |
|---|---|---|---|
| 電子郵件 | 文字輸入（type=email、required，自動聚焦，placeholder `name@example.org`） | 空 | 前端：去除空白、轉小寫；必須包含 `@`。後端：格式需符合 `^[^@\s]+@[^@\s]+\.[^@\s]+$`，且網域須在 `ALLOWED_DOMAINS` 內 |
| 角色 | 下拉選單 | 一般使用者 | 選項：系統管理員、Agent 建置者、一般使用者 |
| 群組 | 下拉選單 | 未設定（空字串） | 選項：「未設定」加上 12 個群組 |

**按鈕**：取消（關閉）、預先註冊（送出）。點擊遮罩或右上角 ✕ 也會關閉。

**送出流程**

1. 前端檢查 email 是否包含 `@`；不通過則 toast「請輸入有效的電子郵件」，對話框保持開啟。（欄位為 `required` 與 `type=email`，瀏覽器會先行攔截，見第 9 節 #15。）
2. 呼叫 `POST /api/users`。
3. 成功：關閉對話框，toast「已預先登錄 {email}」，重新載入列表。
4. 失敗：toast「預先登錄失敗：…」，對話框保持開啟，欄位內容保留。

**後端回應錯誤**（會以 toast 顯示；網域檢查只在 `ALLOWED_DOMAINS` 有設定時進行）

| 狀況 | HTTP | 後端訊息（原文） |
|---|---|---|
| email 格式錯誤 | 422 | `invalid e-mail` |
| 網域不在允許清單 | 422 | `{網域} is not an allowed sign-in domain` |
| 群組不在清單 | 422 | `unknown department {群組}` |
| 帳號已存在 | 409 | `this e-mail already has an account` |

**稽核**：寫入 `user.preregister`。

## 5. 編輯畫面（UserEdit）

進入時呼叫 `GET /api/users/{email}`；載入失敗 toast「載入使用者失敗：…」並返回列表。

### 5.1 標題列

- **返回使用者列表**（左上，ArrowLeft）：回到列表並重新載入。未儲存的變更會直接遺失，**沒有確認提示**（待確認）。
- 標題：編輯使用者。標題下方副標題：「調整同仁的角色、所屬群組，或停用其存取。」
- **檢視個人稽核記錄**（ClockCounterClockwise）：僅當 `goAudit` 存在時顯示。目前實作只會跳到「稽核記錄」頁，**不會帶入此使用者的篩選條件**（見第 9 節）。

### 5.2 個人資料卡

**左側**

- 頭像、姓名（無姓名時「（尚未登入）」）。
- 標題旁的標籤：角色徽章、狀態徽章（停用／啟用，與列表規則相同）；若為固定管理員顯示「固定管理員（部署設定）」；若為本人帳號顯示「這是您自己的帳號」。
- 電子郵件（小字）。
- **所屬群組**：下拉選單，可編輯；不受 `locked` 影響，本人與固定管理員都可修改（見 5.3）；唯讀模式（`readOnly`）時 disabled。
- **擁有資源統計**（唯讀標籤）：
  - N 個 Agent（M 個已發布）
  - N 個連接器
  - N 份知識文件

**右側（dl 清單）**

| 標籤 | 值 |
|---|---|
| 帳號建立 | `created_at`；若有 `created_by`，附註：`migrate_users` 顯示「既有建置者移轉」，其他顯示「{建立者} 預先註冊」 |
| 首次登入 | `first_login_at`，無值顯示「尚未登入」 |
| 最後活動 | `last_seen_at` |

### 5.3 鎖定提示

唯讀模式時另顯示警示「您為唯讀檢視，無法變更使用者資料。」

`locked` = 本人、固定管理員或唯讀模式。當本人或固定管理員時，顯示警示：

- 本人：「不能變更自己的角色與狀態，請由另一位管理員操作。」
- 固定管理員：「此帳號列在部署設定 ADMIN_EMAILS，永遠是管理員且不能停用，避免平台被鎖住。需變更請由資訊室重新部署。」
- 兩者結尾都附加：「所屬群組仍可修改。」

### 5.4 帳號狀態區塊

- 標題：帳號狀態
- 說明文字：
  - 若有 `status_changed_at`：「上次由 {操作者} 於 {時間} 設為{停用／啟用}：{原因}」
  - 否則：「停用會立即阻擋平台存取；恢復後依原角色繼續使用。」
- 兩個選項（單選卡片，可整體點選）：
  - **正常啟用**（`active`）：可用院內 Google 帳號登入平台，依角色使用 Agent Hub、建置與管理功能。
  - **暫停使用**（`suspended`，紅色樣式）：立即阻擋平台 API（其他伺服器執行個體最多 30 秒內生效），並停用 Google 登入、撤銷登入權杖。Agent、連接器與知識文件保留不動，可隨時恢復。
- `locked` 時兩個選項皆 disabled。

### 5.5 角色區塊

- 標題：角色
- 說明：「每位同仁只有一個角色，決定能使用哪些功能。」若有 `role_changed_at`，附加「上次由 {操作者} 於 {時間} 變更」（`migrate_users` 顯示為「系統移轉」）。
- 三張角色卡片（單選，`locked` 時 disabled）。每張卡片顯示：
  - 名稱與英文名，目前角色加註「目前角色」徽章
  - 描述
  - 權限標籤：
    - 系統管理員：發布核可、監控與成本、資安稽核、帳號管理
    - Agent 建置者：Agent Studio、申請發布、連接器、知識庫上傳
    - 一般使用者：已發布 Agent 對話
- **降級警示**：當「原角色非一般使用者」且「改為一般使用者」且「此人擁有任何 Agent／連接器／文件」時，顯示黃色警示，列出此人擁有的 N 個 Agent、N 個連接器與 N 份知識文件，說明這些項目仍歸此人所有但此人無法再編輯；已發布的 Agent 照常上線，管理員仍可編輯。此警示**只提示，不阻擋**儲存。

### 5.6 原始檔檢視區塊

- 標題：原始檔檢視
- 說明：知識庫文件預設只顯示去識別化內容；含個資的原始檔僅授權人員可開啟，且每次必須填寫用途，每次開啟寫入稽核記錄。若有 `original_view_changed_at`，附加變更者與時間。
- 兩個選項：
  - 不可檢視含個資的原始檔（預設）：未偵測到個資的文件仍可開啟原始檔。
  - 可檢視含個資的原始檔（需填用途）：適用於需要核對原文、表格或頁面的臨床同仁。
- 本人或唯讀模式時兩個選項皆 disabled；本人時並顯示警示「不能變更自己的原始檔檢視權限，請由另一位管理員操作。」（說明文字仍可閱讀）
- **注意**：此區塊的 disabled 只看「是否本人」或唯讀模式，**不受固定管理員影響**（與後端一致，見第 6 節）。

### 5.7 變更原因

- 只有在「角色、狀態或原始檔檢視權限」有變動時才出現。
- 標題旁有紅色必填標記 `*`。
- 文字區：最多 200 字，右下角顯示「N / 200」。
- placeholder：「例如：轉調護理部，改為一般使用者；留職停薪，停用存取。」
- 說明：「原因會連同變更前後的角色、狀態或原始檔檢視權限寫入稽核記錄。」

### 5.8 預先註冊帳號的取消

- 僅當 `!uid`（尚未登入）時顯示整列：「此帳號為預先註冊，對方尚未登入過。如果登錄錯誤，可以直接取消。」與紅色按鈕「取消預先註冊」（唯讀模式不顯示按鈕）。
- 點擊後以 `window.confirm` 確認：「取消 {email} 的預先註冊？對方之後登入時會以「一般使用者」建立帳號。」
- 確認後呼叫 `DELETE /api/users/{email}`，toast「已取消預先註冊」，返回列表。失敗時 toast「取消失敗：…」，留在編輯畫面。
- 後端只允許刪除未登入過的預先註冊；已登入的帳號回應 409，訊息為 `this person has signed in; suspend the account instead`。

### 5.9 底部儲存列（savebar）

| 元素 | 規則 |
|---|---|
| 左側文字 | 「正在編輯 {姓名或 email}」；有變更時附上變更摘要（例如「角色 A → B、停用帳號、群組 → X」） |
| 左側提示 | 已儲存且無新變更：「已儲存並寫入稽核記錄。」；需要原因：「變更角色、狀態或原始檔檢視權限需要填寫原因。」；其他：「角色與狀態的變更會寫入稽核記錄。」 |
| 取消變更按鈕 | 唯讀模式不顯示；有變更時才可按；按下後把表單重設為最近一次載入的資料（不呼叫 API） |
| 儲存按鈕 | 唯讀模式不顯示；無變更、需要原因但未填、或儲存中時 disabled。文字：儲存中…／確認停用並儲存／儲存變更。若本次為「停用」，按鈕為紅色 |

**摘要規則**：各項變更以「、」連接，例如「角色 一般使用者 → Agent 建置者、群組 → 護理部」。角色、停用／恢復、原始檔檢視、群組四類依此順序出現；原始檔檢視變更顯示「授予原始檔檢視」或「撤銷原始檔檢視」。

**儲存流程**

1. 組出 patch：只包含有變動的欄位（`role`、`status`、`original_view`、`department`），並帶上 `reason`（去除空白）。
2. 呼叫 `PATCH /api/users/{email}`。
3. 成功：以回傳資料重設表單，左側提示顯示「已儲存並寫入稽核記錄。」，toast 為「已儲存並寫入稽核記錄」。
4. 失敗：toast「儲存失敗：…」，表單內容保留。

## 6. 業務規則彙整

| # | 規則 | 前端（UI） | 後端（強制） |
|---|---|---|---|
| R1 | 需 `users` 才可編輯；`users-viewer` 唯讀 | 無權限顯示限制訊息；唯讀時停用控制項、隱藏寫入按鈕 | `require_permission("users")`（讀）／`write=True`（寫、匯出）；`admin` 角色一律通過 |
| R2 | 不能變更自己的角色或狀態 | 本人時角色、狀態 disabled | 409 `you cannot change your own role or status` |
| R3 | 不能變更自己的原始檔檢視權限 | 本人時整區 disabled | 409 `you cannot change your own original-file access` |
| R4 | 固定管理員（ADMIN_EMAILS）不能變更角色或狀態 | 角色、狀態 disabled | 409 `this admin is set by ADMIN_EMAILS; ...` |
| R5 | 角色、狀態、原始檔檢視變更必須填原因 | 未填原因時儲存 disabled | 422 `a reason is required ...` |
| R6 | 不能移除最後一位有效管理員 | **無前端預先檢查**，只在儲存後顯示錯誤 | 409 `cannot remove the last active admin`（停用或降級時判斷） |
| R7 | 群組必須在清單內（或空白） | 只能從下拉選單選擇 | 422 `unknown department ...` |
| R8 | 固定管理員的群組仍可修改 | 可修改 | 允許 |
| R9 | 降級且有資源時提示 | 黃色警示，不阻擋 | 不阻擋 |
| R10 | 停用會撤銷 Firebase 帳號與登入權杖 | 停用時按鈕改為「確認停用並儲存」 | 寫入 Firebase；失敗僅記錄 log，稽核的 `firebase_synced` 會為 false，**不回報前端** |
| R11 | 只能取消未登入過的預先註冊 | 只在 `!uid` 時顯示按鈕 | 已登入則 409 |
| R12 | 預先註冊的網域需在允許清單 | 只檢查 `@` | 422 |
| R13 | 同一 email 不可重複建立 | 無 | 409 |

## 7. API 對照

| 動作 | 方法與路徑 | 前端函式（`api.js`） | 回應 |
|---|---|---|---|
| 取得列表 | `GET /api/users` | `listUsers()` | `{ users, domains }` |
| 取得單一使用者 | `GET /api/users/{email}` | `getUser(email)` | 使用者詳情含 `owned` |
| ~~取得群組（群組篩選用）~~ | ~~`GET /api/groups`~~ | ~~`listGroups()`~~ | 2026-10-30 移除 `Group` 篩選器後，本頁不再呼叫 |
| 匯出 CSV | `GET /api/users/export.csv` | `usersCsv()`（Blob） | CSV，含 UTF-8 BOM，欄位：email、name、role、status、department、bootstrap_admin、first_login_at、last_seen_at、created_by、status_reason、status_changed_by、status_changed_at |
| 預先註冊 | `POST /api/users` | `preregisterUser(email, role, department)` | 201，使用者詳情 |
| 更新 | `PATCH /api/users/{email}` | `updateUser(email, patch)` | 使用者詳情 |
| 取消預先註冊 | `DELETE /api/users/{email}` | `cancelPreregistration(email)` | 204 |

錯誤處理：`api.js` 的 `call()` 在非 2xx 時拋出 `Error("{狀態碼} {detail}")`，頁面以 `errText()`（只移除開頭的 `Error: ` 前綴）顯示。因此 toast 會帶 HTTP 狀態碼前綴，例如「預先登錄失敗：422 invalid e-mail」，後端的英文訊息會原樣顯示給使用者。
