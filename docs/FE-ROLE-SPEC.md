## 1. 存取與可見性

| 項目 | 規則 | 來源 |
|---|---|---|
| 選單位置 | 側欄「治理」群組，順序為 使用者管理 → **角色管理** → 群組管理 → 用量與成本 | `App.jsx` `adminNav` |
| 選單可見對象 | `me.permissions` 含 `roles` 或 `roles-viewer` 者（`canRoles`）；`roles` 可編輯，`roles-viewer` 唯讀 | `App.jsx` `adminNavPerm`、`visibleAdminNav` |
| 頁面前端防護 | 無 `roles` 與 `roles-viewer` 時只顯示「沒有角色管理權限，請聯絡系統管理員。」，不呼叫 API；僅有 `roles-viewer` 時為唯讀（隱藏新增、刪除、儲存與各清單的新增／移除，表單欄位 disabled） | `RolesPage.jsx` `canEdit`、`canView`、`readOnly` |
| 後端防護 | 讀取需 `roles` 或 `roles-viewer`，寫入需 `roles` | `backend/app/routers/roles.py` |
| 路由 | 內部頁面鍵值 `page === 'Roles' && canRoles` | `App.jsx` |

> 前端判斷只作為 UI 便利，實際權限以後端為準。

## 2. 頁面結構

同一元件以狀態切換三種畫面：

1. **角色列表**（預設）：`RolesPage`
2. **新增角色對話框**：在列表上方疊加 `CreateRoleModal`（需 `roles`），建立後直接開啟該角色的細節頁
3. **角色細節**：點選列表的一列後，以 `RoleDetail` 取代整個內容區；點「返回角色列表」回到列表。細節頁含基本資料、權限（`RolePermissions`）、指派使用者與關聯群組（`RoleLinks`）三個清單，以及多選加入對話框（`AddLinksModal`）

## 3. 角色列表

### 3.1 標題列

| 元素 | 文字 / 圖示 | 狀態 | 行為 |
|---|---|---|---|
| 標題 | 角色管理（IdentificationBadge） | 永遠顯示 | — |
| 按鈕 | 重新整理（ArrowClockwise） | 載入中 disabled，圖示旋轉 | 重新呼叫 `GET /api/roles`；失敗時保留目前列表 |
| 按鈕（主要） | 新增角色（Plus） | 僅 `roles` 顯示；可點擊 | 開啟新增角色對話框（3.6） |

說明文字：「檢視平台角色的權限範圍與目前指派人數。角色變更請至「使用者管理」進行。」

### 3.2 統計卡片（三張）

來源為 `GET /api/roles` 的 `stats`，未載入或失敗時顯示「—」。統計不受搜尋與分頁籤影響。

| 卡片 | 數值 |
|---|---|
| 角色總數 | `stats.total_roles` |
| 系統預設角色 | `stats.system_roles` |
| 自訂角色 | `stats.custom_roles` |

### 3.3 搜尋與分頁籤（ListToolbar）

- 搜尋框 placeholder：「搜尋角色名稱」，即時在前端過濾，比對名稱、英文名稱、說明，不分大小寫。
- 分頁籤（單選，預設「全部」）：**全部**、**系統預設**（`custom === false`）。搜尋與分頁籤為 AND 關係。
- 列表一次載入全部角色，沒有分頁。前端不傳 `search` / `type` 參數給後端。

### 3.4 表格

欄位（欄寬 `2.4fr 1fr .8fr 24px`）：

| 欄位 | 內容 |
|---|---|
| 角色 | 圖示＋名稱（粗體）＋說明（小字）。圖示依 `id`：`admin` 盾牌、`builder` 扳手、`user` 人形，未知 `id` 使用通用圖示 |
| 類型 | 標籤「系統預設」或「自訂」，依 `custom` |
| 狀態 | 「啟用」（綠色）或「停用」（灰色），依 `status`（**`true` = 啟用**） |
| `>` | 箭頭，表示可點選進入細節 |

- 每一列可用滑鼠點選，或在焦點上按 Enter 開啟細節頁。
- 列順序沿用 API 回傳順序，前端不另外排序。
- 空狀態：「沒有符合條件的角色。」
- 載入中：API 未回應前整個表格區域顯示 `Loading`。
- 表格下方固定提示：「角色與功能對應目前為平台內建設定。管理員帳號另可由部署設定 ADMIN_EMAILS 固定指定。」

### 3.5 錯誤處理

- 列表載入失敗：toast「載入角色失敗：…」；首次載入失敗時統計顯示「—」、表格顯示空狀態，重新整理失敗則保留原資料。不會自動重試。

### 3.6 新增角色對話框（CreateRoleModal）

版型與「新增群組」相同，標題「新增角色」。

| 欄位 | 規則 |
|---|---|
| 角色名稱 | 必填，最多 40 字（自動取得焦點） |
| 說明 | 選填，最多 300 字 |

- 按「建立」送出（送出中顯示「建立中…」） `POST /api/roles`，成功後 toast「已建立角色」，關閉對話框，開啟新角色的細節頁，並重新載入列表。
- 名稱為空時顯示「請輸入角色名稱」（超過 40 字的檢查「角色名稱不可超過 40 字」被 `maxLength` 擋下，實際不會出現）。
- 錯誤：403 → 「權限不足，請聯絡系統管理員」；422 → 「資料格式不正確，請檢查輸入內容」；其他 → 「操作失敗：…」。
- 點擊對話框外的背景、按「取消」或右上角 × 都會關閉。目前不支援 Esc 鍵關閉（與「新增群組」一致）。

## 4. 角色細節（RoleDetail）

### 4.1 版面

- 上方：「← 返回角色列表」與標題（角色名稱）。
- 副標題：一般角色為「編輯角色的名稱、說明與狀態，並設定權限。」；`admin` 為「系統管理員為固定角色，不可編輯。」；唯讀（`roles-viewer`）為「唯讀檢視，您沒有編輯角色的權限。」
- 表單卡片「基本資料」，依序為下列欄位，共用一個「儲存」按鈕。
- 表單下方依序為「權限」、「指派使用者」、「關聯群組」三張卡片（4.3、4.6），各自即時儲存，不經「儲存」按鈕。
- `admin` 時底部另顯示提示：「管理員為系統預設角色，權限固定為全部允許，不可在此修改。」

### 4.2 欄位

| 欄位 | 編輯 | 規則 |
|---|---|---|
| 角色名稱 | 可編輯 | 必填，最多 40 字，去除前後空白 |
| 英文名稱（非必填） | 可編輯 | 最多 40 字，可清空 |
| 說明 | 可編輯 | 最多 300 字 |
| 狀態 | 開關（`Toggle`） | `true` = 啟用，`false` = 停用；旁邊顯示文字「啟用」或「停用」 |

### 4.3 權限（RolePermissions）

- 標題「權限（N）」，說明：「選取此角色可執行的平台資源。目前僅記錄設定，尚未套用到功能存取；權限矩陣尚未開放。」
- 資源目錄來自 `GET /api/permissions`；載入失敗 toast「載入權限資源失敗：…」。
- 清單欄位：資源、說明、移除（×）。搜尋框 placeholder「搜尋資源名稱或說明」。空狀態：「尚未設定權限」；搜尋無結果為「沒有符合條件的資料。」
- 「新增權限」（Plus）開啟多選對話框（`AddLinksModal`，4.6）；沒有可加入的資源時 disabled。
- 每次新增或移除即送出 `PATCH /api/roles/{id}`，只帶 `permissions`（完整 id 清單）；成功 toast「已更新權限」，失敗 toast「更新權限失敗：…」並保留原清單。
- `admin` 與唯讀時不顯示新增與移除。

### 4.4 儲存與返回

- 「儲存」只有在內容有變更時可按。送出 `PATCH /api/roles/{id}`，帶入 `name`、`en`、`desc`、`status`（不含 `can` 與 `permissions`）。成功後 toast「已更新角色」，並同步更新列表資料。
- 送出中按鈕顯示「儲存中…」。名稱為空時顯示「請輸入角色名稱」。失敗時於表單內顯示「儲存失敗：…」。
- 有未儲存變更時按返回，會以確認對話框詢問「放棄未儲存的變更？」。
- `admin` 與唯讀（`roles-viewer`）的表單欄位、開關皆 disabled；`admin` 的儲存按鈕 disabled，唯讀時不顯示儲存與「刪除角色」按鈕。

### 4.5 刪除角色

- 位置：標題列右側的「刪除角色」按鈕（紅字，與「刪除群組」相同的版型），唯讀時不顯示。
- 啟用條件：只有自訂角色可按。`admin` 顯示 disabled，提示「管理員不可刪除」；`builder`、`user` 顯示 disabled，提示「內建角色無法刪除」。
- 按下後開啟確認對話框：「確定要刪除「{角色名稱}」？刪除後，群組中的此角色關聯也會一併移除。」，按鈕為「取消」與「刪除」。
- 成功：toast「已刪除角色」，回到列表，列表與統計重新載入。
- 失敗：toast「刪除失敗：…」，對話框保持開啟。刪除中按鈕顯示「刪除中…」。

### 4.6 指派使用者與關聯群組（RoleLinks）

| 項目 | 指派使用者 | 關聯群組 |
|---|---|---|
| 標題 | 指派使用者（N） | 關聯群組（N） |
| 資料來源 | `GET /api/users`，篩出 `roles` 含此角色者 | `GET /api/groups`，篩出 `role_ids` 含此角色者 |
| 欄位 | 姓名、電子郵件、群組、狀態（啟用／停用） | 名稱、說明、成員數 |
| 搜尋 placeholder | 搜尋姓名、電子郵件或群組 | 搜尋群組名稱或說明 |
| 空狀態 | 尚未指派使用者 | 尚未關聯群組 |
| 新增 | 「指派使用者」，`PATCH /api/users/{email}` 帶 `roles` | 「關聯群組」，`PATCH /api/groups/{id}` 帶 `role_ids` |

- 說明文字：使用者「僅記錄指派，不影響任何存取權限；使用者的實際存取仍由「使用者管理」中的角色決定。」；群組「僅記錄關聯，不影響任何存取權限。」
- 每列右側 × 可移除（toast「已移除使用者／群組：…」，失敗「移除失敗：…」）；載入失敗 toast「載入使用者／群組失敗：…」。
- 新增按鈕開啟 `AddLinksModal`：可搜尋、勾選多筆，底部顯示「已選 N 筆」，按「加入（N）」逐筆送出。部分失敗時 toast「已加入 N 筆，M 筆失敗：…」並保持對話框開啟；全部成功 toast「已加入 N 筆」。沒有候選項時新增按鈕 disabled。
- 這兩個清單對 `admin` 角色仍可編輯，僅唯讀（`roles-viewer`）時隱藏新增與移除。清單最多顯示約 5 列，其餘捲動（`.rl-scroll`）。

## 5. 業務規則彙整

| # | 規則 | 前端 | 後端 |
|---|---|---|---|
| R1 | 只有管理員可進入 | 顯示限制訊息，不呼叫 API | `require_admin` |
| R2 | 系統管理員的編輯與停用不可用 | 細節頁唯讀，開關 disabled | `PATCH admin` 回 403 |
| R3 | 自訂角色可新增，系統角色不可新增 | 新增對話框建立的都是自訂角色 | `POST` 寫入 `custom: true` |
| R4 | 狀態 `true` 為啟用，缺少欄位視為啟用 | 依 `status` 顯示 | 同左 |
| R5 | 角色的權限、指派使用者與關聯群組僅記錄 | 各卡片說明文字提示 | 不參與存取判斷 |
| R6 | 角色指派在「使用者管理」進行 | 列表說明文字 | 使用者的 `role` 欄位 |
| R7 | 只有自訂角色可刪除 | 細節頁「刪除角色」僅對自訂角色啟用，其餘 disabled 並顯示原因 | `DELETE` 對內建角色回 403 |

## 6. API 對照

| 動作 | 方法與路徑 | 前端函式 |
|---|---|---|
| 角色列表與統計 | `GET /api/roles` | `api.listRoles()` |
| 新增自訂角色 | `POST /api/roles` | `api.createRole({name, desc})` |
| 修改角色 | `PATCH /api/roles/{id}` | `api.updateRole(id, {name, en, desc, status})`；權限清單另以 `api.updateRole(id, {permissions})` |
| 刪除角色 | `DELETE /api/roles/{id}` | `api.deleteRole(id)` |
| 權限資源目錄 | `GET /api/permissions` | `api.listPermissions()` |
| 指派使用者 | `GET /api/users`、`PATCH /api/users/{email}` | `api.listUsers()`、`api.updateUser(email, {roles})` |
| 關聯群組 | `GET /api/groups`、`PATCH /api/groups/{id}` | `api.listGroups()`、`api.updateGroupInfo(id, {role_ids})` |

群組管理的「角色」欄位也使用 `GET /api/roles`，只取 `id` 與 `name`。使用者管理的角色下拉選單使用 `constants.js` 的 `ROLES`。

## 9. 維護注意

- 指派使用者與關聯群組使用 `/api/users`（目前需 `users`／管理員）與 `/api/groups`；僅有 `roles` 權限的非管理員可能無法載入或指派（**待確認**，見 `frontend/AGENTS.md` 2026-11-03）。
- 修改頁面結構時，同步更新 `frontend/README.md`、`frontend/SUMMARY.md` 與 `frontend/AGENTS.md` 的決策紀錄。
- `Toggle` 位於 `ListKit.jsx`，新增的 `disabled` 屬性由角色細節頁使用。
- 圖示對應表（`ICON`）以角色 `id` 為鍵。新增系統角色時需同步補上，否則使用通用圖示。
- 本頁不在模擬模式中。
