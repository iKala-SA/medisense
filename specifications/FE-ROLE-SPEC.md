# 角色管理功能規格書（前端現況）

| 項目 | 內容 |
|---|---|
| 文件性質 | 目前前端實作的整理（as-built），供後續調整參考 |
| 範圍 | 管理員後台「角色管理」：角色列表、新增角色對話框、角色細節頁 |
| 主要程式 | `frontend/src/live/RolesPage.jsx`（列表、`CreateRoleModal`、`RoleDetail`）、`frontend/src/live/roles.css`、`frontend/src/api.js`（`listRoles`、`createRole`、`updateRole`）、`frontend/src/ListKit.jsx`（`ListToolbar`、`Toggle`、`Empty`）、`frontend/src/App.jsx`（路由與選單） |
| 後端對照 | `specifications/BE-ROLE-SPEC.md`（`GET`、`POST`、`PATCH /api/roles`） |
| 執行模式 | 僅即時模式（`!MOCK`）顯示 |
| 版本基準 | 分支 `remove-deferred-role-features`，2026-11-02 |

> **範圍說明**：刪除角色、權限矩陣（資源 × 操作）、單一角色的細節 API 與變更原因欄位均為 **暫緩**，目前不在實作範圍。權限標籤只能編輯文字，不會影響存取。
>
> 本文件以程式碼為準。標示為「**待確認**」的項目需與負責人確認。

## 1. 存取與可見性

| 項目 | 規則 | 來源 |
|---|---|---|
| 選單位置 | 側欄「治理」群組，順序為 使用者管理 → **角色管理** → 群組管理 → 用量與成本 | `App.jsx` `adminNav` |
| 選單可見對象 | 僅系統管理員 | `App.jsx` `go()` 阻擋非管理員進入管理頁 |
| 頁面前端防護 | `me?.role !== 'admin'` 時只顯示「此頁面僅限系統管理員。」，不呼叫 API | `RolesPage.jsx` |
| 後端防護 | `/api/roles` 全部端點以 `require_admin` 保護 | `backend/app/routers/roles.py` |
| 路由 | 內部頁面鍵值 `page === 'Roles'` | `App.jsx` |

> 前端判斷只作為 UI 便利，實際權限以後端為準。

## 2. 頁面結構

同一元件以狀態切換三種畫面：

1. **角色列表**（預設）：`RolesPage`
2. **新增角色對話框**：在列表上方疊加 `CreateRoleModal`，建立後直接開啟該角色的細節頁
3. **角色細節**：點選列表的一列後，以 `RoleDetail` 取代整個內容區；點「返回角色列表」回到列表

---

## 3. 角色列表

### 3.1 標題列

| 元素 | 文字 / 圖示 | 狀態 | 行為 |
|---|---|---|---|
| 標題 | 角色管理（IdentificationBadge） | 永遠顯示 | — |
| 按鈕 | 重新整理（ArrowClockwise） | 載入中 disabled，圖示旋轉 | 重新呼叫 `GET /api/roles`；失敗時保留目前列表 |
| 按鈕（主要） | 新增角色（Plus） | 可點擊 | 開啟新增角色對話框（3.6） |

說明文字：「檢視平台角色的權限範圍與目前指派人數。角色變更請至「使用者管理」進行。」

### 3.2 統計卡片（三張）

來源為 `GET /api/roles` 的 `stats`，未載入或失敗時顯示「—」。統計不受搜尋與分頁籤影響。

| 卡片 | 數值 |
|---|---|
| 角色總數 | `stats.total_roles` |
| 系統預設角色 | `stats.system_roles` |
| 自訂角色 | `stats.custom_roles` |

### 3.3 搜尋與分頁籤（ListToolbar）

- 搜尋框 placeholder：「搜尋角色名稱」，即時在前端過濾，比對名稱、英文名稱、說明，不分大小寫。
- 分頁籤（單選，預設「全部」）：**全部**、**系統預設**（`custom === false`）。搜尋與分頁籤為 AND 關係。
- 列表一次載入全部角色，沒有分頁。前端不傳 `search` / `type` 參數給後端。

### 3.4 表格

欄位（欄寬 `2.4fr 1fr .8fr .8fr 24px`）：

| 欄位 | 內容 |
|---|---|
| 角色 | 圖示＋名稱（粗體）＋說明（小字）。圖示依 `id`：`admin` 盾牌、`builder` 扳手、`user` 人形，未知 `id` 使用通用圖示 |
| 類型 | 標籤「系統預設」或「自訂」，依 `custom` |
| 狀態 | 「啟用」（綠色）或「停用」（灰色），依 `status`（**`true` = 啟用**） |
| 成員數 | `{member_count} 人` |
| `>` | 箭頭，表示可點選進入細節 |

- 每一列可用滑鼠點選，或在焦點上按 Enter 開啟細節頁。
- 列順序沿用 API 回傳順序，前端不另外排序。
- 空狀態：「沒有符合條件的角色。」
- 載入中：API 未回應前整個表格區域顯示 `Loading`。

### 3.5 錯誤處理

- 列表載入失敗：toast「載入角色失敗：…」，統計顯示「—」，表格顯示空狀態。不會自動重試。

### 3.6 新增角色對話框（CreateRoleModal）

版型與「新增群組」相同，標題「新增角色」。

| 欄位 | 規則 |
|---|---|
| 角色名稱 | 必填，最多 40 字（自動取得焦點） |
| 說明 | 選填，最多 300 字 |

- 按「建立」送出 `POST /api/roles`，成功後 toast「已建立角色」，關閉對話框，開啟新角色的細節頁，並重新載入列表。
- 名稱為空時顯示「請輸入角色名稱」。
- 錯誤：403 → 「權限不足，請聯絡系統管理員」；422 → 「資料格式不正確，請檢查輸入內容」；其他 → 「操作失敗：…」。
- 點擊對話框外的背景、按「取消」或右上角 × 都會關閉。目前不支援 Esc 鍵關閉（與「新增群組」一致）。

## 4. 角色細節（RoleDetail）

### 4.1 版面

- 上方：「← 返回角色列表」與標題（角色名稱）。
- 副標題：一般角色為「編輯角色的名稱、說明、狀態與權限標籤。」；`admin` 為「系統管理員為固定角色，不可編輯。」
- 表單卡片「基本資料」，依序為下列欄位，共用一個「儲存」按鈕。
- 權限標籤卡片的內容也在同一表單內。
- `admin` 時底部另顯示提示：「管理員為系統預設角色，權限固定為全部允許，不可在此修改。」

### 4.2 欄位

| 欄位 | 編輯 | 規則 |
|---|---|---|
| 角色名稱 | 可編輯 | 必填，最多 40 字，去除前後空白 |
| 英文名稱（非必填） | 可編輯 | 最多 40 字，可清空 |
| 說明 | 可編輯 | 最多 300 字 |
| 狀態 | 開關（`Toggle`） | `true` = 啟用，`false` = 停用；旁邊顯示文字「啟用」或「停用」 |
| 類型 | 唯讀 | 顯示「系統預設」或「自訂」，附註「（由角色代號決定，不可修改）」 |
| 權限標籤 | 可新增、可移除 | 見 4.3 |

### 4.3 權限標籤

- 以標籤（chip）顯示目前的標籤；每個標籤有 × 可移除。沒有標籤時顯示「尚未設定」。
- 輸入框（placeholder「輸入後按 Enter 新增」）與「新增」按鈕：按 Enter 或按鈕新增。
- 規則：去除前後空白後不可為空；每個最多 20 字；最多 20 個；重複的標籤不會重複加入。
- 錯誤訊息：「權限標籤不可超過 20 字」、「權限標籤最多 20 個」。
- 說明文字：「目前僅供顯示，尚未套用到功能存取；權限矩陣尚未開放。」

### 4.4 儲存與返回

- 「儲存」只有在內容有變更時可按。送出 `PATCH /api/roles/{id}`，帶入 `name`、`en`、`desc`、`status`、`can`。成功後 toast「已更新角色」，並同步更新列表資料。
- 名稱為空時顯示「請輸入角色名稱」。失敗時顯示「儲存失敗：…」。
- 有未儲存變更時按返回，會以確認對話框詢問「放棄未儲存的變更？」。
- `admin` 的所有欄位與按鈕都是唯讀。

## 5. 業務規則彙整

| # | 規則 | 前端 | 後端 |
|---|---|---|---|
| R1 | 只有管理員可進入 | 顯示限制訊息，不呼叫 API | `require_admin` |
| R2 | 系統管理員的編輯與停用不可用 | 細節頁唯讀，開關 disabled | `PATCH admin` 回 403 |
| R3 | 自訂角色可新增，系統角色不可新增 | 新增對話框建立的都是自訂角色 | `POST` 寫入 `custom: true` |
| R4 | 狀態 `true` 為啟用，缺少欄位視為啟用 | 依 `status` 顯示 | 同左 |
| R5 | 權限標籤僅供顯示 | 說明文字提示 | 不參與存取判斷 |
| R6 | 角色指派在「使用者管理」進行 | 列表說明文字 | 使用者的 `role` 欄位 |

## 6. API 對照

| 動作 | 方法與路徑 | 前端函式 |
|---|---|---|
| 角色列表與統計 | `GET /api/roles` | `api.listRoles()` |
| 新增自訂角色 | `POST /api/roles` | `api.createRole({name, desc})` |
| 修改角色 | `PATCH /api/roles/{id}` | `api.updateRole(id, {name, en, desc, status, can})` |

群組管理的「角色」欄位也使用 `GET /api/roles`，只取 `id` 與 `name`。使用者管理的角色下拉選單使用 `constants.js` 的 `ROLES`。

本頁的新增與修改會由後端寫入稽核紀錄（`role.create`、`role.update`）。前端不直接寫稽核。

## 8. 已知問題與待確認事項

| # | 項目 | 說明 | 建議 |
|---|---|---|---|
| 1 | 狀態變更沒有原因欄位 | 使用者管理要求填寫原因，角色細節頁沒有 | **待確認**：是否比照使用者管理加入 |
| 2 | 權限標籤不影響存取 | 使用者可能誤以為已設定權限 | 權限矩陣完成前維持說明文字 |
| 3 | 列表的搜尋與篩選在前端執行 | 後端支援 `search` / `type`，前端未使用 | 資料量增加時改為傳參數 |
| 4 | 新增角色的 `id` 由系統產生 | 無法指定可讀的代號（2026-11-02 決定：暫不開放自訂，由系統產生） | 已決定，維持現況 |
| 5 | 系統角色名稱與說明可被覆寫 | `admin` 以外的系統角色可由 PATCH 修改名稱 | **待確認**：是否要鎖定 `builder` |
| 6 | 對話框不支援 Esc 關閉 | 角色與群組的新增對話框都未實作 Esc | 與群組一併統一 |
| 7 | 列表不會自動更新 | 需手動按重新整理 | 可考慮加入自動刷新 |
| 8 | 未在瀏覽器驗證 | 目前只通過建置與後端測試 | 上線前完成手動檢查 |

## 9. 維護注意

- 修改頁面結構時，同步更新 `frontend/README.md`、`frontend/SUMMARY.md` 與 `frontend/AGENTS.md` 的決策紀錄。
- `Toggle` 位於 `ListKit.jsx`，新增的 `disabled` 屬性由角色細節頁使用。
- 圖示對應表（`ICON`）以角色 `id` 為鍵。新增系統角色時需同步補上，否則使用通用圖示。
- 本頁不在模擬模式中。
